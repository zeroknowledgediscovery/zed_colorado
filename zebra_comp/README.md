# curated_2 — reproducible ZeBRA + genomics manuscript analyses

This directory is the minimal analysis package for the current manuscript framing. Historical preprocessing/model notebooks `01` and `02` are excluded. The canonical global comparison starts with `32_COMBINED_CLASSIFIERS.ipynb`.

## Scientific analysis chain

1. `32_COMBINED_CLASSIFIERS.ipynb`
   - primary global comparison
   - repeated held-out evaluation of ZeBRA, genomics-only, and combined ZeBRA+genomics models
   - also produces calibration/zedstat/operating-point and SHAP summaries

2. `33_INCREMENTAL_LOGISTIC_ANALYSIS.ipynb`
   - supporting robustness analysis, not required for the headline result
   - asks whether genomics adds conditional predictive information after ZeBRA in a regularized logistic framework

3. `test_zebra_muc5b_apparent_association.py`
   - intentionally pooled/descriptive analysis
   - asks whether ZeBRA appears associated with MUC5B rs35705950 T-carrier status before conditioning on FILD
   - generates the two manuscript-framing figures:
     - `ZEBRA_BY_MUC5B_T_CARRIER.png`
     - `ZEBRA_MUC5B_NONLINEAR_ASSOCIATION.png`
   - this result must not be interpreted as evidence that ZeBRA reconstructs genotype

4. `testinverse_muc5b_stratified_by_fild.py`
   - critical clarification of the pooled association above
   - repeats ZeBRA–MUC5B association/enrichment analyses within FILD-positive and explicitly FILD-negative strata
   - the pooled association largely disappears within disease strata, supporting the interpretation that the apparent pooled ZeBRA–MUC5B relationship is consistent with both quantities tracking FILD status rather than ZeBRA recovering MUC5B genotype

5. `test_local_zebra_genomics_predictive_curves.py`
   - maps where MUC5B/genomic information is locally informative for FILD prediction across the ZeBRA score distribution

6. `test_muc5b_zebra_rescue_matched_fpr_lr.py`
   - primary decision-boundary analysis
   - uses MUC5B only between a stringent high ZeBRA threshold and a lower rescue threshold, then compares against ZeBRA at matched empirical FPR

7. `test_zebra_hybrid_roc_convex_hull_zedstat.py`
   - supporting ROC/convex-hull/zedstat analysis of attainable operating points

The deliberately excluded fixed-percentile switch experiment is not part of this curated lineage.

### Intended manuscript logic

The MUC5B analyses are deliberately ordered to avoid a misleading interpretation:

```text
Pooled ZeBRA–MUC5B association
        ↓
apparent concordance between clinical trajectory and genotype
        ↓
stratify on FILD status
        ↓
pooled association largely disappears
        ↓
therefore do not interpret ZeBRA as reconstructing MUC5B genotype
        ↓
ask the separate predictive question:
does MUC5B still provide local information for FILD classification?
        ↓
local-information + matched-FPR boundary analyses
```

A suitable interpretation is: *In pooled analyses, ZeBRA is weakly associated with MUC5B rs35705950 carrier status. This relationship is markedly attenuated after stratification by FILD status, consistent with shared association to disease status rather than recovery of genotype from the clinical trajectory. Nevertheless, MUC5B can provide locally useful information for FILD classification near selected ZeBRA operating boundaries.*

## Required processed inputs

The complete manuscript run starts from three processed files in this directory.

### `ILD_TOP_DRIVERS_DATA.csv`

This is the processed Colorado genomic feature matrix. It is treated as an input to the manuscript analysis, not regenerated by `run_all.sh`.

It must satisfy the following contract:

- one row per Colorado participant represented in the genomic analysis
- a unique/joinable `patient_id` column
- genomic predictor columns encoded numerically; the historical construction used one-hot encoded genotype states
- no ZeBRA score is required in this file; ZeBRA `predicted_risk` is merged separately from `PREDICTIONS_104W_PRED_WINDOW.parquet`
- no phenotype label should be used as a genomic feature
- a historical `target` column is tolerated by the analyses and dropped, but it is not required and should preferably be absent
- the current MUC5B analyses require the three one-hot columns:

```text
rs35705950.1_G_0
rs35705950.1_G_1
rs35705950.1_G_2
```

Historical encoding for rs35705950 is interpreted as:

```text
rs35705950.1_G_2 = GG
rs35705950.1_G_1 = GT
rs35705950.1_G_0 = TT
```

A valid called genotype has exactly one of those columns equal to 1. An all-zero row represents an unavailable/missing original genotype after `pd.get_dummies(dummy_na=False)` and must not be interpreted as TT or as a T-risk carrier.

The runner validates the required columns before starting.

### How `ILD_TOP_DRIVERS_DATA.csv` was historically generated

The archived `01_GATHER_GENDRIVER_DATA.ipynb` is intentionally not included here because it depended on restricted data and hard-coded cluster paths. Its relevant preprocessing logic was:

1. Read the raw Colorado genotype matrix/header.
2. Read the prior biological-driver SNP list (`biological_drivers.csv`).
3. Read the additional candidate list `MORE_LOCI.csv`.
4. Form candidate identifiers using both SNP rsIDs and `CHR:BP` coordinates.
5. Match those identifiers to raw genotype headers. Historical genotype headers ended in an allele suffix, so matching was performed on the header prefix.
6. Select the matched genotype columns and map subject identifiers to `patient_id`.
7. One-hot encode the categorical genotype states.
8. Write the resulting participant-by-genomic-feature matrix as `ILD_TOP_DRIVERS_DATA.csv`.

In the archived run, `MORE_LOCI.csv` contained 3,113 candidate rows and 148 additional raw genotype columns matched that list before union with the earlier biological-driver set. The resulting processed matrix contains the genomic features used by the downstream analyses.

For a future raw-data rebuild, place restricted source data under `colorado_data/` and implement/validate the preprocessing against the contract above. Do not assume the archived absolute filesystem paths.

### `REPHENOTYPES FOR IC.csv`

Adjudicated phenotype/outcome file. The analysis code converts `arb_person_id` to `patient_id` and constructs the manuscript targets using the same logic as notebook 32.

### `PREDICTIONS_104W_PRED_WINDOW.parquet`

ZeBRA prediction file. It must contain at least `patient_id` and `predicted_risk`. The manuscript analyses retain participants with a non-missing `predicted_risk`.

## Run everything

From `curated_2/`:

```bash
./run_all.sh
```

is equivalent to:

```bash
./run_all.sh full
```

For a short validation run:

```bash
./run_all.sh fast
```

Every run first deletes and recreates `RESULTS/`, so it contains only outputs generated by that run.

## Ancillary genomic-header utility

`scripts/find_phenotype_genomic_headers.py` is independent of the manuscript run. It maps HFrEF, IPF, or ADRD gene panels to matching rows in a one-column `genomicdataheader.csv`, using GRCh37 gene intervals and Ensembl variation annotations.

Example:

```bash
python scripts/find_phenotype_genomic_headers.py \
    colorado_data/genomicdataheader.csv --panel IPF
```
